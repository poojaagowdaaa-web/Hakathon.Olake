https://olake.io/docs/ || OLake supported sources: OLake can ingest data from 8 sources: PostgreSQL (Postgres), MySQL, MongoDB, Oracle, MSSQL (SQL Server), IBM DB2, Apache Kafka and Amazon S3.
https://olake.io/docs/ || OLake supported destinations: OLake writes to two destinations: Apache Iceberg tables (through a catalog such as Glue, Hive, JDBC or REST) and Parquet files on object storage such as Amazon S3. Delta Lake, Hudi, Snowflake and BigQuery are not supported destinations.
https://olake.io/docs/ || Not supported: Cassandra is not supported as a source in OLake. Delta Lake is not a supported destination. OLake supports only these sources: PostgreSQL, MySQL, MongoDB, Oracle, MSSQL, IBM DB2, Kafka and S3, and writes only Apache Iceberg tables and Parquet files.
https://olake.io/docs/understanding/terminologies/olake/ || Sync modes: OLake supports four sync modes: Full Refresh, Full Refresh + CDC, Full Refresh + Incremental, and CDC Only.
https://olake.io/docs/understanding/terminologies/olake/ || Incremental sync: Full Refresh + Incremental does a full load first, then each later run reads only rows whose cursor value is greater than the last synced value, which is saved in state. An optional secondary cursor is used when the primary cursor is null. It captures new rows, and updates if the cursor is a timestamp like updated_at, but it does not capture deletes.
https://olake.io/blog/olake-architecture-deep-dive || CDC is not continuous: an OLake CDC sync is a bounded session, not a daemon. It notes where the log ends at start, streams changes up to that point (or until nothing new arrives within initial_wait_time), commits, then exits. Near-real-time comes from scheduling it often, for example every few minutes (schedule).
https://olake.io/docs/connectors/postgres/setup/generic/ || Postgres CDC setup: PostgreSQL 10+ with the built-in pgoutput plugin. Set wal_level = logical, enough max_replication_slots and max_wal_senders (senders above slots), and wal_sender_timeout = 0, then restart. Allow replication in pg_hba.conf, give a user the REPLICATION role and SELECT access, then create a publication and a logical replication slot and give both names to OLake.
https://olake.io/docs/connectors/mysql/setup/generic/ || MySQL CDC setup: MySQL 5.5+ (5.7+ recommended). Binary logging on with binlog_format = ROW and binlog_row_image = FULL, binlog_row_metadata = FULL on MySQL 8.0+, and a unique server-id. The user needs SELECT, REPLICATION CLIENT and REPLICATION SLAVE privileges.
https://olake.io/docs/connectors/mongodb/cdc_setup/ || MongoDB CDC setup: MongoDB must run as a replica set, which enables the oplog. On Atlas this is already set up. You can check the oplog with db.oplog.rs.findOne() in the local database.
https://olake.io/docs/understanding/terminologies/general/ || Metadata columns: OLake adds _op_type (r = snapshot read, c = insert, u = update, d = delete), _olake_id (deterministic ID used for dedup), _olake_timestamp (when OLake wrote the row) and _cdc_timestamp (when the change happened at the source, for CDC). Some drivers add CDC position columns, such as _cdc_lsn for Postgres.
https://olake.io/docs/understanding/terminologies/olake/ || Upsert vs Append: Upsert keeps only the latest version of each key, with no duplicates. Append writes every change as a new row and keeps the full history. The default is Upsert, except Kafka, which defaults to Append. It can be overridden per stream, and Full Refresh always appends.
https://olake.io/docs/understanding/compatibility-catalogs/ || Iceberg catalogs: OLake can write to AWS Glue, Hive Metastore, JDBC, and REST catalogs: generic REST, Nessie, Polaris, Unity, Lakekeeper, S3 Tables, BigLake and Horizon.
https://olake.io/docs/understanding/compatibility-engines/ || Query engines: engines on the compatibility page that can read the Iceberg tables OLake writes include Amazon Athena, Apache Spark, Apache Flink, Trino, Presto, Dremio, DuckDB, ClickHouse, StarRocks, Snowflake, Databricks, BigQuery (BigLake) and AWS Redshift. Support for each catalog and delete format varies by engine.
https://olake.io/docs/install/olake-ui/ || Install OLake UI locally: run curl -sSL https://raw.githubusercontent.com/datazip-inc/olake-ui/master/docker-compose-v1.yml | docker compose -f - up -d, then open http://localhost:8000 and log in with admin / password. Change the defaults in x-signup-defaults in the compose file before starting.
https://olake.io/docs/community/commands-and-flags/ || OLake CLI commands: spec (config schema for a connector), check (test a connection), discover (generate streams.json), sync (needs --config, --streams and --destination) and clear-destination (clear data for the selected streams).
https://olake.io/docs/getting-started/job-level-properties/ || Scheduling a job: yes, besides presets (every minute, hourly, daily, weekly), OLake accepts a custom cron expression in 5-field and 7-field formats. Quartz cron syntax is not supported.
